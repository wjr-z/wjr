# 基础库任务流

本流程用于并行推进 arch、容器和 C++20 基础设施。以可用功能和明确问题为交付单位，
不按文件数或 MR 数凑工作量。待审上限遵循用户最新指示，当前为 16；已合入项不计数。

## 队列与任务卡

协调者维护四类队列：功能交付、必要修复、性能研究、工程效率。
有可执行的功能任务时，为功能线保留实施容量；零散修复不能无限占据全部实施槽位。
阻碍当前功能的正确性问题先解决，其他发现进入待办，避免连续扩大正在实现的任务。

每张任务卡包含以下字段。小任务允许合并说明，不能省略结果与验收条件。

| 字段 | 内容 |
| --- | --- |
| id / kind / domain | 稳定编号、任务类别、负责模块 |
| outcome | 用户可观察的结果或可复现的问题 |
| priority / rationale | 优先级及实际调用、影响或用户需求证据 |
| dependencies | 必要依赖，以及依赖未完成时仍可独立推进的部分 |
| owner / write_scope | 负责人、工作树和允许修改的文件范围 |
| contract | 输入域、所有权、失败行为及应保留的性能前提 |
| acceptance | 最小充分验证和明确的完成标准 |
| state / evidence / MR | 当前阶段、验证证据、远端 MR 链接 |

本地执行卡可放在忽略的 `tools/foundation-workflow/tasks.json`。
卡片记录分工和意图；进程、分支、MR 和 CI 的实际状态必须从对应工具重新核对。

## 状态与交接

任务依次经历 `ready → running → validating → submitted → merged`。
`blocked` 必须写明具体外部依赖；等待某次 CI 不能阻止独立任务运行。
研究任务也可结束为 `rejected`：保存结论和紧凑证据，不把无收益候选强行并入生产。

进入 `ready` 前确定写入范围、合同、依赖和验收。工作树隔离并不代表可以同时修改
同一模块的不兼容设计；共享接口的修改由一个负责人协调，其他任务使用稳定边界。

实施者完成自审和必要验证后可按已有授权提交、推送并创建 MR。
父代理并行审查关键差异、语义和证据，不重复子代理已完成的完整构建。
提交后保留修复本人 CI 的责任，同时领取下一个无依赖任务。

## 模型与调度

- Luna：范围明确的源码盘点、资料整理、译文、运行日志提取和任务卡草稿。
  输出须含可核查的位置或数据；不能把未经核实的总结当作实现依据。
- Sol high：源码实现、针对性验证、生成码检查和 MR 交付。
  负责人在同一任务中完成这些步骤，避免每个小步骤都交回父代理等待批准。
- Astra：具有广泛影响的设计取舍和集中审查。先准备源码、合同、成熟实现和实验结果，
  一次审查形成可执行决定；不用于常规修复、格式化或反复读取 CI 状态。

按依赖图调度，而不是按发现顺序排长队。当前可并行的典型组合是一个 arch 功能、
一个容器功能和一个 CI 效率任务。平台或复杂度不同不意味着要复制整个实现。

## 验证预算

简单薄包装、同谓词约束迁移和明显等价修复，使用针对性行为／编译检查及格式检查。
影响访存、分支、内联、布局或 relocate/move 分派的复杂改动，才追加相应生成码或测量。
有新改动、失败或未解决疑点才扩大或重复验证；不为每个提交重新做全部研究。

先核实设计意图与合法输入域。故意受限的高性能原语不能因越过前提的测试失败而扩域。
需要更宽输入域时，评估独立接口及实际调用方；原有可信路径保持其前提和实现优势。
只在性能敏感结构及关键 relocate/move 路径检查优化 traits，不能将其变成普通代码负担。

## CI 与发布节奏

先完成一个可审查版本再推送，减少同一 MR 的连续小修订。
必要修订的 CI 可以取消同一 PR 的过时版本；其他 PR、main 和手动验证保持独立。
分别记录排队时间、执行时间、缓存命中和测试时间，不能把 runner 排队当作编译退化。
不通过删除编译器、标准、ISA、sanitizer 或安装消费者覆盖来制造提速。

达到待审上限后暂停新增 MR，继续完成已提交项的必要修正，并等待用户审核。
合入释放名额后，重新核对依赖和下一批优先级。涉及共同接口或出现冲突时刷新相关分支；
堆叠 MR 在前置项 squash 合并后须去除重复补丁，必要推送使用精确 force-with-lease。
检查新 head 的 CI 确实已触发，不为无关合入强制重跑全部分支。

## 资源收尾

每批合入后核对闲置工作树、分支和构建。仅清理已证明不再需要的 agent 产物，
检查未跟踪文件、活跃进程、共享依赖及最终 MR head；保留用户文件和紧凑证据。
Windows 删除使用经过绝对路径白名单核对的原生操作，远端 ref 使用精确 SHA lease。
