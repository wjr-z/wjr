# constexpr 算法的标准库边界

`wjr::constant` 保留现有函数名、参数和返回类型，复用标准库的算法实现。
`copy`、`move_backward`、`merge` 和 `sort` 在 C++20 下可参与常量求值。
不再维护另一套始终采用插入排序的实现，也不在 merge 前遍历输入求距离。
因此单遍输入不会被预先消耗，排序接受可移动但不可复制的元素。

原来的 `__cpp_lib_algorithms` 不是标准特性宏，导致标准库分支始终不可达。
正确的特性宏是 `__cpp_lib_constexpr_algorithms`，C++20 基础值为 `201806L`，
见 [LWG 3256](https://cplusplus.github.io/LWG/issue3256)。

`inplace_merge` 包装器返回 `last`，保持其原先声明的返回语义。
它在 C++20/23 标准库上提供运行期调用；只有标准库报告
`__cpp_lib_constexpr_algorithms >= 202306L` 时才声明为 `constexpr`。
这项能力来自 [P2562R1](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2022/p2562r1.pdf)，
不因选择较新的语言模式就假定实现已经支持。

这些包装器遵循对应标准算法的迭代器、比较器、输出容量和重叠前提。
`merge` 保持稳定性；`sort` 不提供稳定排序保证。运行期排序复用标准库的
复杂度和小区间策略，不对任意输入规模承诺优于直接调用标准库。

测试同时覆盖编译期排序、复制、合并和反向移动，运行期单遍流输入、稳定合并、
move-only 元素、空区间、重复键和自定义顺序。大区间比较次数测试用于拒绝原先的
二次增长路径，不是吞吐量或分支预测性能基准。

Clang 18、MSVC 19.42 标准库、`-O3 -march=x86-64` 下，4096 个确定交错值的
外部探针记录到比较次数从 3,992,778 降为 75,334。它说明这组输入避开了原来的
插入排序路径；没有测量运行时间或硬件计数器，也不据此推断小区间性能。
